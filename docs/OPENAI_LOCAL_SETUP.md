# ESEPTEP: существующий ключ, локальная подготовка без платных запросов

Ключ `eseptep-ai-production` уже создан владельцем. Новые ключи не создаются.
Основной Windows checkout: `C:\Users\Жаник\Desktop\eseptep`.
Секрет вручную вставляется только в `C:\Users\Жаник\Desktop\eseptep\.env`, в `OPENAI_API_KEY=`.
Не отправляйте значение в чат, Git, PR, скриншот или лог. `.env` и `.env.*` исключены из Git; `.env.example` содержит только безопасные значения.

`python manage.py prepare_ai_env` только добавляет отсутствующие переменные и не перезаписывает уже существующие. Django читает `.env` через python-dotenv; переменные текущего процесса имеют приоритет. Открыть файл: `notepad .env`.

## До подтверждения владельца

Оставить `OPENAI_LIVE_CONFIRMED=0`, `PLAN_AI_ENABLED=0`, `ESTIMATE_AI_ENABLED=0` даже после вставки ключа. Наличие ключа само по себе не включает платные вызовы. Для проверки настройки **без сети**:

```powershell
Set-Location 'C:\Users\Жаник\Desktop\eseptep'
.\.venv\Scripts\python.exe manage.py check_ai_setup
.\.venv\Scripts\python.exe manage.py check
```

Не запускайте migrate/seed поверх старой пользовательской базы ради демонстрации. Проверенная демоверсия использует отдельную SQLite-базу и private-media, назначаемые `ops/start-meeting-demo.ps1`; старые db.sqlite3/media сохранены. Этот скрипт специально оставляет plan API выключенным.

## Архитектура

Один `core/openai_client.py` использует официальный `openai==3.55.0`, Responses API, фиксированный официальный endpoint, `store=False`, `max_retries=0`, таймаут 45 секунд (настройка ограничена 5–60), максимум 1800 выходных токенов. Ключ существует только на backend.

Существующий анализ планов не дублируется: `projects/plan_analysis.py` заменил urllib на общий SDK boundary и сохраняет прежние страницы/размеры/подтверждение/дедупликацию. Модель выбирается `OPENAI_MODEL`; разрешены проверенные по опубликованным тарифам `gpt-5.4-mini-2026-03-17` и прежняя `gpt-4.1-mini-2025-04-14`. Первая выбрана по умолчанию, **её доступность в аккаунте и живой результат ещё не проверены**. Неизвестная модель блокируется до обновления расчёта бюджета.

На странице сохранённой сметы появилось отдельное действие «Объяснить смету». Оно отправляет только параметры и материалы сохранённого расчёта, а не проект, имя, контакты или файл плана. Ответ RU/KK кэшируется для сметы/языка, HTML экранируется. ИИ не меняет формулы, числа или сохранённую смету. Повторное нажатие/обновление не вызывает повторный запрос. Уведомление перед кнопкой объясняет передачу в OpenAI.

Оба сценария используют **один существующий PlanAnalysisBudget, id=1**, максимум 200 центов зарезервировано на пилот. Перед попыткой резервируются 20 центов, в том числе при неизвестном исходе/таймауте. Автоповтора и автоматического возврата резерва нет. Это консервативный счётчик приложения, не точный расход и не лимит биллинга организации. Новый checkout/пустая БД не дают новый бюджет $2. Перед live-тестом нужно сверить старые попытки, определить один постоянный ledger и подтвердить остаток. Никакие seed/setup-команды его не обнуляют.

## После отдельного сообщения владельца «ключ вставлен, можно проверить»

Сначала проверяются флаги, постоянная БД/резервы и выбранная модель; затем включается ровно необходимый сценарий и выполняется один минимальный тест на обезличенных данных. Результат фиксируется с моделью, usage и оценкой расхода. До этого момента платных запросов нет. Не включать оба сценария и не открывать публичный доступ заранее.

Для тестов нет необходимости в настоящем ключе: все тестовые ответы OpenAI подменены. Не использовать клиентские документы, production и API-тесты из GitHub Actions.

Смена языка страницы сама по себе бесплатна. Явное создание объяснения на втором языке — отдельный запрос с отдельным резервом20¢; уже полученный текст повторно не запрашивается. Удаление исходной загрузки плана удаляет её dedup-запись, но не возвращает денежный резерв.
