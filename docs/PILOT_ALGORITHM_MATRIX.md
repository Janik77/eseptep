# Границы расчётного пилота ESEPTEP

Аудит программной реализации 18 ноября 2026, исходная цепочка PR #71–76.
Это не заключение о соответствии строительным нормам и не инструкция монтажа.

## Исправленные программные дефекты

- Электрика: дробная площадь рядом с эталоном больше не получает эталонный комплект как будто площадь целая. 59,99 / 60 / 60,01 м² проверены для 2 и 3 комнат. Для дробных значений действует уже существующее масштабирование, а не новая норма.
- Плитка: 20,01 м² и 50,01 м² больше не считаются точными эталонами 20/50. Количества масштабируются существующим алгоритмом, целые эталоны сохранены.
- Плитка: эталон выбирается только среди той же зоны и формата. Расстояние по площади больше не может подменить выбранную категорию.
- Для «Пол + крупный формат» и «Санузел полностью + крупный формат» в исходной матрице нет комплектов. Новый расчёт явно отклоняется с сохранением ввода. Старые сохранённые сметы не пересчитываются и не удаляются. Возвращать эти сочетания следует только после добавления подтверждённой методики.
- ГКЛ: дробная площадь не помечается точным совпадением при определении существующих бюджетных коэффициентов вариантов. Это не подтверждает цены этих вариантов.

Никакие seed-команды или миграции исторических результатов этим изменением не выполняются.

## Матрица допуска

«Кандидат» означает только возможность ограниченного демонстрационного пилота **после** подтверждения исходных цен и методики владельцем/специалистом. Ни один калькулятор не сертифицирован этими тестами.

| Калькулятор | Статус для пилота | Что необходимо подтвердить / ограничение |
|---|---|---|
| Демонтаж | Кандидат, предварительный список расходников | Состав работ, объём мусора и вывоз, площадь защиты плёнкой. Существующий коэффициент 1,20 не реализует альтернативный расчёт «радиаторы + дверь». |
| Электрика | Только демонстрационная оценка; не монтажный проект | Нагрузки, кабель, защита, точки и комплектации. Эталон 60 м² / 3 комнаты не подтверждён заказчиком; исправление программного lookup не подтверждает его содержание. |
| Сантехника | Только демонстрационный расчёт до согласования комплектаций | Измеренные трассы и точки, наборы вариантов; дополнительная сумма Business 150 000 ₸ не имеет определённого состава. |
| Штукатурка | Только демонстрационный расчёт до проверки норм | Стены=3×площадь пола, 10% проёмов, смесь 0,30 мешка/(м²·см), округление грунтовки вниз и фиксированные инструменты. |
| ГКЛ | Только демонстрационный расчёт до проверки матриц | Реальные размеры/периметр/тип конструкции, бюджетное масштабирование стоимости вариантов, все комплектующие. |
| Наливной пол | Кандидат для конкретного согласованного продукта | Расход по паспорту продукта, толщина в сантиметрах, мешок 25 кг; опубликованный коэффициент сам по себе не гарантирует применимость продукта. |
| Плитка | Кандидат только для имеющихся сочетаний | Нормы и фасовки клея/грунтовки/фуги, запас и основание. Два отсутствующих сочетания программно заблокированы, остальные не сертифицированы. |
| Ламинат / SPC / паркет | Кандидат только для прямой укладки | Список материалов использует +5%; диагональ/ёлочка в метриках только сравнение, не переключатель состава. Подтвердить упаковки, основание и плинтус. |
| Малярка | Только демонстрационный расчёт до проверки норм | Вычисленная площадь стен, реальный вид отделки, коэффициенты и округление расхода. |
| Натяжной потолок | Только демонстрационная оценка | Реальная геометрия, периметр, свет и ниши; округление дробных количеств может не соответствовать продаже по м². |
| Двери | Не использовать как заказную комплектацию до решения альтернатив | В исходном списке одновременно обычный/магнитный замок и обычные/скрытые петли. Нет утверждённого выбора пользователя; автоматически удалять одну альтернативу нельзя. |
| Тёплый пол | Только демонстрационная оценка; не проект монтажа | Нужны теплотехника, допустимая мощность/нагрузка, гидравлика, шаг и ограничения трасс, подтверждённые комплектации. |

Статусы таблицы — ограничения сдачи. Они не означают, что все предупреждения/блокировки автоматически внедрены в интерфейс: программно закрыты именно отсутствующие сочетания плитки. Другие калькуляторы продолжают показывать прежние предварительные результаты; перед внешним коммерческим пилотом ограничить доступ к неподтверждённым методикам либо получить их подтверждение.

## Проверки и нерешённые вопросы

- Существующая параметризованная проверка всех 12 функций: все допустимые выборы, границы, соседние площади 19,99 / 20 / 20,01 и варианты комнат; арифметика строк и итогов. Для двух отсутствующих комплектов ожидается ошибка, не выдуманный результат.
- Новая проверка дробных полей учитывает также `floor_area` и `thickness`, запятую, все варианты и соответствие сумм.
- Проверено отсутствие мутации исходных матриц при расчёте. Хранение исторических смет остаётся snapshot-механизмом существующей реализации.
- Общий `_round_quantity` исторически округляет числа ≥10 до целого и меньшие до одного знака. Изменять это массово без согласованной единицы/фасовки и версии методики нельзя. Точность ввода и точность выходного количества — разные вещи.
- Граница ближайшего эталона способна менять состав/расход скачком; монотонность и физическая корректность интерполяции ещё требуют методологического решения.
- Тесты подтверждают программное поведение и арифметику, но не фактическую цену, наличие, пригодность SKU или достаточность закупки.

## Persistence retries (pilot)

Rendered results carry a signed intent bound to the authenticated user, calculator
and input fields. Each `(user, nonce, action)` has a unique database receipt; project,
variant and displayed snapshot versions are frozen in its fingerprint. A replay of
the same submission redirects to the original calculation, even after price editions
change. A changed payload under an already consumed key fails closed. Selecting a
different action is a separate intentional operation; a fresh calculation creates a
fresh intent and can intentionally be saved separately.

Receipt, calculation and optional master/supplier request commit atomically. Failed
writes leave no partial estimate or consumed receipt. No session-only lock or
client-only button disable is relied upon. Anonymous/foreign/unsigned intents are
rejected; ordinary project and client-role permission checks remain. Migration
`accounts.0003_calculationsubmission` adds only a new table; old calculations are not
backfilled or rewritten. Application rollback should retain this table and receipts
to preserve retry protection. The previous application version did not enforce
idempotency, so do not replay pending saving POSTs against that version.

`tools/qa_submission_concurrency.py` uses two independent connections and an isolated
file-backed SQLite DB, holding the first transaction open while the second repeats
its request. Expected: same calculation ID, one receipt, one calculation, one service
request. SQLite write-lock timeout can still cause a transient failure under extended
contention, but the client must retry the *same* intent, never silently create another.
PostgreSQL concurrency was not exercised in this pilot.

New admin quotations use method revision
`reference-quantities@pilot-exact-match-v2`. Historical quotation snapshots retain
the revision stored at their original save time.
