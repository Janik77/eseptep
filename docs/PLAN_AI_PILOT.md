# План → ванная → плитка пола (тестовая версия)

## Что работает

Загрузка в существующем разделе → приватная растровая копия плана → отдельная кнопка «Разобрать план» с уведомлением о передаче в OpenAI → редактируемые помещения → подтверждение ванной → существующий калькулятор плитки пола → вариант → опубликованный прайс → сохранение исходных данных и версии цен.

Площадь стен не подставляется из площади пола. Нераспознанное значение пустое. Подтверждённый источник подписан и принадлежит владельцу загрузки. Если изменить площадь прямо в калькуляторе, нужно вернуться к плану и повторно подтвердить её. Смета хранит собственный снимок подтверждения, а не динамическую ссылку на текущий ответ ИИ. Повторное сохранение одного результата использует механизм идемпотентности PR77.

PDF отображается растровой копией, не исполняемым документом. Ссылка на страницу существует только для допустимого номера страницы; строка текстового слоя показывается только при точном совпадении цитаты с извлечённым текстом. Это **не** утверждение о номере строки экспликации. Координатной подсветки нет: надёжная привязка не реализована. Ответ ИИ всегда требует проверки человеком.

## Честный статус

Живой вызов OpenAI ещё **не выполнен**. В доступной ChatGPT-среде не найден поддерживаемый защищённый способ настроить серверный ключ; Codex-only setup не использован. Ключ не создавался, реальные документы не отправлялись. Модель: `gpt-4.1-mini-2025-04-14`, фиксированный снимок, поддержка structured outputs. Модель помечена провайдером deprecated; перед подключением необходимо проверить доступность в проекте. Автоматической замены модели нет.

Количество реальных запросов: **0**, расход: **$0**, время живого распознавания: не измерено. Backend тесты используют явно подставленный API-ответ. Browser script проверяет **ручной fallback**, не выдаёт его за распознавание ИИ.

## Ограничение затрат

Только непроизводственная среда; `PLAN_AI_ENABLED=0` по умолчанию. Один файл до 5 МБ, максимум две страницы PDF; изображения до 20 Мп, растры уменьшаются до 1600 px. Ответ ограничен 1800 токенами, 20 помещениями, 64 КБ. Нет инструментов модели, автоматических повторов и клиентского API-ключа; `store=false` (это не обещание нулевого хранения по правилам провайдера).

Перед запросом атомарно резервируется $0.20 из постоянного общего счётчика $2 в БД. Не более 10 попыток на эту БД. Таймаут или сбой НЕ возвращает резерв: исход оплаты может быть неизвестен. Не удалять/сбрасывать эту БД и счётчик между испытаниями; лимит не агрегируется между разными БД или другими приложениями организации. Не запускать пилот одновременно на другом стенде с отдельной БД.

Дедупликация по владельцу/гостевой сессии и SHA256 файла: повторный POST, обновление, смена языка и повторная загрузка идентичного файла тем же владельцем не инициируют повторный платный запрос. Смена владельца считается отдельным документом, но расход остаётся в общем лимите БД. Статус `running` после аварии сохраняется и не перезапускается вслепую.

Оценка расходов по документированной цене модели: вход $0.40/1M, выход $1.60/1M. Для двух ограниченных изображений и ответа оценка значительно ниже резервных $0.20. Это резервный технический потолок запросов по указанной фиксированной модели, не настройка биллинга организации. Перед живым прогоном следует подтвердить цену и доступность. Отчёт: `python manage.py plan_pilot_report`; неизвестная стоимость отображается null, не ноль.

Документация: https://developers.openai.com/api/docs/models/gpt-4.1-mini , https://developers.openai.com/api/docs/guides/images-vision , https://developers.openai.com/api/docs/guides/structured-outputs .

## Локальный запуск в существующей папке (PowerShell)

Сначала закрыть runserver, сохранить локальные правки и резервную копию по `docs/PILOT_LOCAL_UPDATE.md`. Ниже не меняется рабочая БД: используется **одна новая изолированная БД пилота**, сохраняемая между попытками.

```powershell
Set-Location 'C:\Users\Жаник\Desktop\eseptep'
git status --short
# При локальных изменениях сначала сохраните их отдельным коммитом. Не reset/clean.
git fetch origin
git switch --track origin/feat/plan-ai-pilot
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:DJANGO_ENV='development'
$env:DJANGO_DB_PATH="$PWD\plan-ai-pilot.sqlite3"
$env:DJANGO_PRIVATE_MEDIA_ROOT="$PWD\plan-ai-private-media"
$env:PLAN_AI_ENABLED='0'
python manage.py migrate
python manage.py test projects calculators accounts core
python manage.py createsuperuser
python manage.py runserver
```

Если ветка уже существует: `git switch feat/plan-ai-pilot; git pull --ff-only`. Для фиксации конкретного проверенного результата используйте SHA из отчёта PR. Не добавляйте новую SQLite БД, файлы планов и секреты в Git. Реальные `.env` никогда не коммитить. Добавление ключа только в защищённую серверную настройку, не в чат или frontend. Когда ключ безопасно подключён и цена проверена: `PLAN_AI_ENABLED=1` в непроизводственной среде, один сервер/одна БД. Не делать тестовый API-запрос вне этого счётчика.

Для сохранения смет нужен **клиентский аккаунт**, а не только superuser: зарегистрируйте тестового клиента через интерфейс. В админке можно опубликовать синтетический прайс тестового магазина. Без опубликованного прайса показывается только справочная сумма, магазин не выдумывается.

## Повтор browser QA

`tools/qa_plan_pilot.mjs` использует только localhost:8207 и отдельную синтетическую БД, проверяет RU/KK, 1440/390, ручную корректировку, расчёт, выбор варианта, частичный тестовый прайс и сохранение. Требует Playwright и системный Chromium. Установка браузера/зависимостей отдельная, не runtime приложения. Никогда не запускать `tools/qa_browser_seed.py` на существующей пользовательской БД.

Не реализованы в этом этапе: координатная подсветка, распознавание произвольных сложных планов без проверки, автоматическая площадь стен, обработка клиентских документов в production. Коммерческую готовность этот пилот не подтверждает.
